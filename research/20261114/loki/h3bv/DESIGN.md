# H3bv prospective rerun with certified computation reductions

H3bu remains incomplete at its original two-million-state cap. H3bv would be a separately frozen execution of all 4,096 archived cases, reacquiring every actual MAP/tree label. It does not resume H3bu, use free completed-case answers, change the original 10,355-call comparator, or weaken the sole realized endpoint: at least 2% fewer total actual calls, at most 10,147. All exact flags must remain equal. No prospective cohort pilot is used.

The scientific policy is H3bu's conservative depth (8-used_MAP) handoff at current sets of at most sixteen models. Any hypothetical original-baseline failure vetoes handoff. The baseline terminal depth remains four. Every branch and candidate is retained; all actual queries are paid. Expected nonincrease and exact-flag equality remain correctness properties, not primary outcomes.

Three measured implementation changes preserve every chosen query: exact Huffman lower bounds prune dominated partitions, compact RAM caches retain only the chosen routing tree after the complete proof is serialized, and equal effective root depth reuses one canonical computation while retaining distinct requested-depth receipts and complete logical proofs. See BOUND_LEMMA.md for the prefix-code exchange proof, strict/equal lexicographic rule and full-body reuse argument.

The compiler orders feasible root partitions by (exact Huffman branch bound, board index), with child information-bound failures last by board. It updates incumbents by (weighted cost, board index), because a later explored option may have an earlier board. A bound strictly above the incumbent prunes; equality prunes only if its board is later. Every ordering bound, evaluated incumbent and two-smallest merge trace is retained. An independent verifier reconstructs the entire order, every merge, every prune and every chosen candidate path, and rejects unreferenced bound cache entries.

Assessment v1 using board order preserved all paths but could find a poor incumbent late; v2 bound order improved the same fixed synthetic suite. All 17,008 cases passed, including 16,960 exhaustive n=2..4 cases covering every canonical query catalog, positive weights from {1,2}, forward/reversed catalog order and depths1..4. Larger n=6,8,10 full/singleton fixtures cover depths4,5,6,8 and uniform/geometric weights. V2 independently checked 755,974 conditions. Reference CPU was2.714694 seconds versus0.610845 for pruning; reference579386 work steps versus240352 pruned partition/merge steps. Charged memo entries increased135780→196102 across this deliberately small-case-heavy suite because every bound-cache entry is honestly charged. No universal state or speed reduction is claimed.

On a separate twelve-set synthetic memory benchmark, unpruned computation used22,320 states,642,432 work steps,3.945994 CPU seconds and420,608KiB peak RSS. Pruned compact caching used12,492 states,55,788 work steps,0.075944 CPU seconds and46,976KiB. Pruned full/compact logical proof bytes were identical; compacting alone reduced61,292→46,976KiB RSS. These local synthetic timings are not a promised cohort speedup.

Equal-effective-depth reuse on105 requested-depth receipts recorded66 canonical hits and reduced8,751→5,541 states and27,783→19,269 work steps. CPU remained about0.084seconds because complete logical proof serialization still occurs. All reused proof bodies were byte-identical to fresh computation, requested depths remained distinct, and original computation hashes remained bound. This optimization targets the observed binding state/work cap rather than claiming a wall-time gain.

Proposed caps remain600 aggregate CPU seconds,900 wall seconds,2,000,000 memo states,50,000,000 work steps,100,000-bit weights and32,768 actual calls. Memo states include tree states, Huffman subset-bound entries and counterfactual nodes. Work steps include canonical tree partition attempts, every Huffman merge and counterfactual MAP partitions. All reference/pruned/cache scientific gates repeat within the run and are charged. Canonical reuse does not recharge nonexistent computations, but hash validation, full proof/input/result serialization and all bookkeeping charge CPU/wall. Logical proof size and actually charged work are separately reported. Any cap/error leaves the whole study incomplete, preserving every case and paid query with no extension.

Prefreeze and independent serialized-fixture gates must pass on Loki. Requested-depth source identities, all original-computation reuse hashes, complete proof body equality and no unreferenced computations are independently audited. Frozen source includes the independent tree/gate verifiers. No protocol is frozen or cohort rerun launched until coordinator review.
