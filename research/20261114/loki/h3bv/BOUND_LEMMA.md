# Exact Huffman lower bounds and tie-safe pruning

For positive integer candidate weights, every separating binary decision tree gives a binary prefix code with those leaf weights. Removing empty or one-child queries cannot increase cost. Huffman's repeatedly merging the two smallest weights minimizes weighted external path length over all unconstrained binary prefix trees. Its exact merge sum is therefore a lower bound for any separating tree using the supplied query catalog and any remaining depth restriction. The scientific tree class is a subset of that unconstrained code class.

For a proposed root partition S=A union B, every valid tree has cost at least mass(S)+H(A)+H(B), where H is that unconstrained Huffman lower bound. If this lower bound exceeds an already established feasible incumbent, the partition cannot improve the optimum. If it equals the incumbent, pruning is permitted only when the proposed root board is lexicographically later than the incumbent's board. A strict improvement remains impossible, and the earlier incumbent wins an equal-cost tie. Options are explored by increasing exact branch lower bound and then board index, with child-information-bound-infeasible alternatives last. A later explored option can therefore have an earlier board index. The incumbent updates by the pair (weighted cost, board index), and the explicit strict-versus-equal pruning rule never discards a possible earlier equal-cost choice. Every ordering bound is recorded and independently reconstructed. It never prunes before a feasible incumbent exists.

Every evaluated bound records the partition masks, lower bound, incumbent cost and incumbent board index. This receipt remains even when the bound is too weak and the branch is subsequently explored. Each distinct subset bound retains the complete two-smallest merge sequence, independently checkable from the original positive integer weights. All bound-cache entries must be referenced by a recorded evaluation. Every bound memo entry charges the global state budget and every Huffman merge charges the global work-step budget, alongside tree states and canonical partition attempts. No uncharged oracle labels or true identity enters any bound.

State normalization min(depth,subset_size-1) remains unchanged. Proofs retain all considered partition alternatives, including certificates for pruned ones. Full proofs are serialized before in-memory caches retain only the chosen routing states, weights, cost and leaf depths. The compact cache changes no on-disk scientific proof bytes or selected query path.

H3bu remains incomplete at its original state cap. Any subsequent cohort study is a separately frozen full 4,096-case execution with every actual MAP/tree label reacquired and charged. It is neither a continuation nor an extension of H3bu's budget, and its realized 2% hypothesis is separate from the mathematical correctness of pruning.

The Huffman minimum follows by an exchange argument and induction. A full binary prefix tree has two sibling leaves at maximum depth. Put the two smallest positive weights at those two deepest positions; exchanging a smaller weight downward with a larger one cannot increase the weighted path sum. Merging those siblings reduces the problem to one fewer leaf with their sum as the new weight, and subtracts exactly that sum from the cost. Repeating the two-smallest merge therefore constructs a minimum-cost unrestricted prefix tree. Tied weights give the same bound; their coding-tree tie choices are irrelevant to the scientific board tie rule.

For effective-depth reuse, the compiler normalizes the root immediately, before any recursive exploration. Fixed candidates, weights and full catalog with equal min(requested_depth, |S|-1) therefore produce identical root states, explored options, bounds, chosen paths and proof body. Only the recorded requested depth differs. A reused receipt keeps its distinct requested-depth input and complete logical proof, and binds the original computation's group, proof hash and result hash. The source proof is read and hash-checked before its requested-depth header is changed. Serialization and hash validation still count toward CPU/wall budgets; reused memo/merge charges are zero because they are not recomputed. Independent auditing compares the entire proof body, source references and requested-depth limits, rather than trusting the reuse flag.
