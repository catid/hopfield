# H3bw prospective full rerun without a Huffman subset cache

H3bu and H3bv remain incomplete at their separate original state caps. H3bw would start all 4,096 archived cases from case zero, reacquire every actual MAP/tree answer, preserve every case and exact flag, and test the same sole endpoint: at least a 2% reduction from the original 10,355-call H3br comparator, at most 10,147. It neither extends a capped budget nor uses completed-case answers for free. No new cohort outcome enters preparation.

The scientific policy and query allowance are unchanged: at up to four paid MAP steps, current sets of at most sixteen candidates may switch to a posterior-optimal tree of requested depth 8-used_MAP. Every hypothetical original-baseline branch uses remaining_MAP steps followed by its original depth-four tree. Any baseline exact=False flag vetoes handoff; every branch and candidate remains recorded. All-case exact-flag equality and conditional expected nonincrease are correctness properties, separate from the realized finite-cohort primary.

A computational diagnostic of completed H3bv computations counted 1,104,711 Huffman memo entries, including 35,440 singleton and 97,402 pair entries. It inspected proof structure only, without calculating any new policy outcome. This diagnostic is descriptive of the stopped prefix.

A fixed synthetic assessment compared full subset memoization, direct singleton/pair bounds, and no subset memoization. All preserve every exact bound, ordering decision, lexicographic optimum and candidate query path. Removing all bound memoization provides a wider state margin and is selected. Every bound is recomputed using the same two-smallest merges, every actual merge is charged, and complete inline certificates are retained at each ordering evaluation. The huffman_bounds registry must be empty. These inline output traces are not consulted by later evaluations; no cache is merely renamed. Independent verification reconstructs every merge using a sorted-list algorithm, every option order and every strict-versus-equal prune.

Across 17,008 synthetic cases, all-inline matches the fully memoized compiler: 196,102 to 85,335 memo entries, 240,352 to 343,407 charged work steps. The suite includes 16,960 exhaustive two-to-four-model cases with every canonical catalog, weights in {1,2}, both catalog orientations and depths one through four. Forty-eight larger full/singleton fixtures cover six, eight and ten models, uniform/geometric weights and depths four, five, six and eight. The full memoized reference is retained and independently audited.

Eight additional fixed larger full/sparse synthetic fixtures use ten, twelve and sixteen models, full catalogs or deterministic random catalogs plus singleton and binary-coordinate queries, and uniform/geometric weights. These are synthetic computational measurements, not a cohort speed or completion promise. All-inline uses more time, work and transient serialization memory while removing the binding bound-cache states. Full traces can be larger; no proof content is discarded to obtain the state reduction.

The already-gated compact RAM routing cache and effective-root tree reuse remain. A complete proof is written before keeping only its chosen routing states in RAM. Equal min(requested_depth, candidate_count-1) can reuse a completed canonical tree computation, with separate requested-depth receipts, source proof/result hashes, and a complete logical proof body whose only changed field is requested depth. This tree-level reuse is separate from the eliminated subset-bound cache. Reused logical proofs remain independently replayable and their hash checks/serialization still consume CPU/wall time.

Caps remain 600 aggregate CPU seconds, 900 wall seconds, 2,000,000 actual tree/counterfactual memo entries, 50,000,000 actual partition/Huffman-merge/counterfactual-MAP work steps, 100,000-bit integers and 32,768 actual calls. Reference and candidate scientific fixtures repeat inside the run and are charged. No persistent Huffman memo entries exist to charge; every recomputation is honestly charged as work. Logical proof counts and actually charged work remain distinct. Any cap/error leaves the entire study incomplete, with all planned cases and paid calls preserved and no extension or partial-primary result.

Complete source, preflight gates and independent serialized-artifact audit require coordinator review before freeze. The former narrow-inline prototype and all assessment source hashes/receipts remain archived. No prospective cohort run is launched during design.
