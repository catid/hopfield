# H3bu prospective design: use the existing total-query budget

The falsifiable primary remains at least 2% fewer actual membership calls than the original H3br baseline of 10,355 on all 4,096 examined cases: at most 10,147. H3bt's 64-call / 0.618059% saving remains a failed primary. No prospective cohort pilot or new outcome is used to design H3bu.

At a current set of at most sixteen candidates after m MAP queries, compile an exact posterior-optimal tree with requested depth 8-m. This uses the same maximum eight actual calls as the original policy, while allowing a deeper continuation earlier. Sets above sixteen remain ineligible and continue the unchanged MAP policy; this is a compute eligibility rule, not an infeasibility certificate.

Preserve the exact-flag comparator by admitting handoff only if **every** hypothetical original-baseline candidate branch identifies. Original terminal trees request depth four. An infeasible terminal contributes zero additional membership queries and exact=False, and every branch remains recorded. Any false exact flag vetoes handoff; there is no truth-conditioned filtering. All original 4,083 exact cases and thirteen failures must remain equal. Cases themselves are never dropped.

The explicit exact integer cost guard remains. If all baseline branches identify, the complete baseline is already a feasible depth (remaining_MAP+4) tree; the new optimum must have no greater cost. A pure cost rejection is therefore a correctness error. This property does not imply a realized 2% finite-cohort reduction.

Depth normalization uses min(remaining_depth, subset_size-1) at every recursive state. A nonconstant query removes at least one other model along any candidate path, so larger depth budgets add no possible nonconstant trees. Requested depth remains separately bound in proof/input/cache keys. The H3bt compiler is untouched; a new compiler is gated against a byte-identical reference copy and an independent all-alternative verifier.

Initial single-thread synthetic assessment on the local coordinator, not the cohort: forty cases spanning depths1..8 retained every cost, feasibility and chosen lexicographic candidate path, with 34,903 independent certificate checks. Reference enumeration used 6,067 states / 39,979 splits / 0.145192 CPU seconds; normalized enumeration used 2,912 / 25,564 / 0.074516. These small-fixture timings are descriptive, not a claim about cohort speed. The first unconstrained-thread timing receipt is retained separately and is not used for the performance comparison. Runtime repeats and charges both reference and normalized gates.

A full-partition six-candidate fixture with weights32,16,8,4,2,1 has depth-four optimum124 versus depth-five-and-deeper119. Separate fixed fixtures at remainingMAP1,2,4 retain six infeasible baseline candidates each and veto the new handoff. Shared-prefix evaluation matches all per-candidate costs and exact flags, with30 selector calls versus152 naive rollouts. Cache keys distinguish requested depths4 and8 even when their effective separating trees coincide.

A state at unnormalized recursion level t has at most n-t remaining models and at most 2^(D-t) models if reached after the compiler's child information bound. Count each candidate subset and remaining depth to bound reachable states; each m-candidate state has at most2^(m-1)-1 canonical nonconstant partitions. For n=16, D=8, this gives303,159 states /83,385,753 split alternatives before normalization, and251,687 /81,911,897 after merging equal effective-depth states. These bounds are per root set and deliberately overestimate any specific sparse board catalog. They show that one pathological set can exceed the existing global50M split cap; normalization is not a universal completion guarantee.

Proposed limits remain the same as H3bt:600 aggregate CPU seconds,900 wall seconds,2,000,000 aggregate states,50,000,000 aggregate splits,100,000-bit weights and32,768 actual calls. These are a bounded feasibility envelope, not a promised complete enumeration. Runtime gates, original-reference gate computations, preparation, serialization, postexecution checks and monitoring all contribute. Any cap or technical failure marks the whole study incomplete, retaining every planned case and paid query; no partial-cohort endpoint, budget extension or cap-as-infeasibility claim is permitted.

Source/design/gates require coordinator review before freeze. No `protocol.json` is created during assessment. The scientific run will execute only after that review, then export every counterfactual and tree certificate with logical byte identities preserved. H3bt's stable public package and export adapter remain unchanged.
